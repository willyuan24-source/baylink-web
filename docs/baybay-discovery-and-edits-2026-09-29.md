# BAYBAY：地点搜索、计划修改与站外补搜

## 本轮行为

- 搜索可返回活动、餐厅、咖啡店、商店、新店和景点。旧活动建议格式保留；新增地点建议和独立的换批排除列表。
- 用户指定店名或新店时保留其意图；一般地点搜索在相关性相同时优先有当前时段和准确坐标的地点。尚未开业、已知当天关闭或不符合明确条件的地点不会混入。
- 真实地点可以单独成为计划起点。资料足够时生成至少两站的完整方案，使用同城、直线距离、官方时段和既有预算条件；资料不足时保留手工安排入口。
- 计划概览显示日期、人数、站点、安排时段、已知金额及预留小计、费用待确认数量。它不是完整报价。
- 一句话修改支持提前/延后、修改开始或结束时间、修改日期、删除明确站点或博物馆、替换为真实餐厅/咖啡店，以及可比已知入场价的更便宜景点。先预览，用户采用后才改草稿，仍需保存。
- “保留地点与时间”保护选中站点及其实际到达/开始/结束时间。混合或含糊要求整句拒绝，官方演出场次不随整趟平移；时间冲突或已知金额超预算禁止采用。未知餐费不作“更便宜”的依据。
- 搜索日期和草稿日期分开；搜索例句、清除搜索条件、语言 URL 参数和移除自动搜索参数不会清空草稿。采用新方案或清除条件会取消旧推荐，晚到响应不能回填。
- 不同账号分别挂载计划工作区，清除上一身份的草稿、偏好输入、结果、锁定及飞行中的请求。公开分享仍只含已发布地点引用和日期。

## 站外搜索边界

用户明确点击后，后端使用现有 OpenAI 凭据调用 Responses `web_search`。只发送当前查询及语言/日期/地区/城市，不发送保存计划、账号或对话历史。UI 把真实引用编号链接到相应来源，显示查询时间、缓存状态和未逐项核实说明。站外结果供核对，不会自动写入公共目录或伪装成可规划地点。

默认独立模型 `gpt-4.1-mini`，一次最多一个工具调用、20 秒超时、10 分钟缓存，每 IP 5 次/分钟及 20 次/滚动日，全站共享 Mongo 原子日额度默认 100 次。提供关闭开关；无凭据、工具失败或无可信来源时明确不可用，不生成假搜索结果。具体可配置项见后端 README 与 `.env.example`。

普通每周营业时段不等同于指定当天已确认营业；检索时间也不是官网的核对日期。交通仍是可修改的预留时间，没有调用 Google Maps Routes 或 Ticketmaster。
