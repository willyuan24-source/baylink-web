# BAYLINK bug audit — 2026-09-11

## Scope and method

Reviewed production public pages, mobile layouts, shared navigation/session code, profiles, messaging, contact permissions, account recovery, sharing, multilingual discovery and everyday calculators. Mutating regression cases ran against local JSDOM fixtures and isolated backend models. No real member messages, profile edits, password resets or contact approvals were submitted for testing.

## Confirmed issues and repairs

### Accounts and private contact information

- A pending profile save, phone verification or official verification could finish after its editor closed or the account changed and replace the current browser session. Editors and callbacks now belong to their initiating account/token and mounted instance. Reopened certification forms start clean; blocked local storage no longer misreports a successful server verification as a failed verification.
- Profile switches could leave the previous person's contact/report/block actions after a failed load. Public profile state is reset and failed profiles do not expose stale actions.
- Changing the login token for the same account did not replace private chat/list instances. Both now isolate pending responses by account and token.
- An existing conversation let approval of an old contact request bypass a later block. Contact sharing now checks the actual participants again. An administrator's approval now uses the actual post owner as sender, rather than opening a conversation as the administrator.
- Concurrent password reset submissions could both consume the same token. The replacement password and token consumption now occur in one conditional database update after hashing.

### Conversations and notifications

- Simultaneous first contact could create duplicate conversations. New two-person conversations use an atomic deterministic pair key; existing conversation IDs remain usable.
- A delayed decline could overwrite another tab's approved contact request. Decline now conditionally transitions only pending requests.
- Omitting a text message's type saved an unrenderable message despite returning success. The backend now saves the normalized type and rejects non-string message text.
- Pending contact badges could show an old session's count or disappear during a network outage. Counts now isolate sessions, cancel obsolete requests, retain the last confirmed count on errors and reject polls superseded by newer inbox counts.

### Navigation, search and sharing

- Closing/completing password reset changed the browser address without updating React Router. Router navigation now replaces the token-bearing history entry; Back/Forward tests cover both paths.
- Traditional queries on a fresh Simplified/English page depended on first visiting the Traditional interface. A small, synchronous search dictionary now makes results independent of language-loading order. The full display conversion dictionary remains lazy-loaded.
- Monthly event filtering now uses the same query normalization; for example, 舞獅 finds the matching event on the Simplified page.
- Post sharing dropped the selected language. Canonical share URLs now retain it.
- Share previews and copied templates could translate authors' titles, locations, budgets, times or custom split-bill names. Interface labels translate while user text remains unchanged.
- If both clipboard mechanisms failed, sharing had no usable fallback; an exception could also leave a hidden textarea behind. The sheet now offers a selectable manual link and always cleans up the temporary control and restores focus.

## Verification

- Production crawl: all 73 sitemap URLs and 103 referenced same-origin image/script assets returned successful responses; no unexpected HTML in asset responses. Evidence: `output/bug-audit-public.json`.
- Production browser: home, monthly edition, loan tools and own-profile page inspected; tested mobile viewport 390×844 without horizontal page overflow, broken loaded images or console warnings/errors in the checked views.
- Frontend `npm run check`: 307 tests passed, TypeScript/build passed, 74 public pages prerendered. ESLint has 0 errors and 38 existing warnings. Existing large-bundle notices remain informational.
- Backend tests exercise races, authorization, normalized messages and compatibility using isolated models. Deployment and final verification results are recorded separately in `output/bug-audit-release.json`.

## Limits

This is a code, regression and browser audit, not a guarantee that every browser, network condition or external service is error-free. SMS delivery, real account recovery and actual private-message/contact writes were not exercised against production. Historical duplicate conversations were preserved to avoid losing or moving existing messages. External attraction/event links and factual editorial freshness were not comprehensively re-researched in this bug-fix pass.
