## 一句话结论

深城纪（GTA_SZ）好看，靠的是三件事：**城市一直铺到地平线、每个视角里都有几个一眼认得出的地标、强烈的光影**。

它的代价也很清楚：
- 340 MB 的资源；
- 只能在电脑上玩；
- 街道层面是空的，这一点它自己的审计也承认。

我们要学的是它的**方法**：
- 数据驱动地铺满整座城；
- 按距离分块加载；
- 一个地标交给一个模块、一个负责人；
- 严格的质量门槛。

它的**画风**我们不学，照片级写实和我们的风格不合。

我们的做法：
- 把整个旧金山做成**一块放在奶油色桌面上的玩具微缩模型**；
- BAYBAY 陪你走遍全城；
- 加上自行车、缆车、叮当车、鹈鹕滑翔和地图快速旅行；
- **手机上照样流畅**。

## 1. 深城纪是怎么做出来的

### 1.1 流水线：数据 → Blender → GLB → 浏览器

1. **数据**：下载 OpenStreetMap 的广东数据包，截取深圳一条 22.6 × 8.7 公里的带状城区，得到 16,076 栋楼和 12,202 条路。
   - 楼高有 59% 是**随机挑的**，因为深圳的开放数据几乎没有楼高。
2. **加工**（Python + Blender）：
   - 把马路合并后切成三角面，加斑马线、路灯和树（离车道太近的树会被自动删掉）。
   - 楼按轮廓"挤出"成体块，再加檐口、店面玻璃和阳台。
   - 52 个知名地标各写一个小 Python 模块单独建模。
3. **打包**：输出成 GLB 3D 文件，按 640 米一块切分：
   - 楼 49.8 MB，路 16.8 MB，精细立面 29.8 MB；
   - 整个城市文件夹 **340 MB**。
4. **运行**：浏览器（Babylon.js 引擎）启动时先载入全城的楼和路，再按距离开关显示。
   - 近处的精细立面一块一块地流式加载：700 米内显示，1,500 米外卸载。
   - 远处的山用 30 米精度的卫星地形数据做成。

### 1.2 画面为什么好看

- **楼不重复**：8 种手绘"立面语法"，加上每栋楼一个随机种子（决定颜色、窗户排列、夜里哪几层亮灯）。
- **夜景可信**：灯按"一整层、一整户"亮，不是随机噪点。
- **远处不闪**：窗户小到看不清时，自动淡成平均色。
- **天空与光影**：用电影级 HDR 天空图（每张 6–20 MB），主光和补光的比例拉得很开，所以立体感强。
- **视野里没有边界**：往哪看都是城市、山和海。
- **每个地标都有一个专门的"拍照机位"**。

### 1.3 移动与载具

- **步行很简单**：走 1.6、跑 4.2，没有加速度，也不能跳。
- **开车**：简化的"自行车模型"物理，最高 53 单位/秒，另有坦克、水上飞机和无人机。
- **地图四个动作**：自动驾驶、画路线、瞬移到路边、俯瞰。
- 让它"像 GTA"的，其实是这些**配套**：
  - 上下车时检查车门旁有没有空间；
  - 跟车相机；
  - 沿道路网自动驾驶；
  - 按模式变化的按键提示。

### 1.4 流程与质量门槛（最值得学）

- **证据阶梯**：每个地标都要走过"计划 → 有证据 → 已建模 → 已验证"四步。改动模型或证据会自动降级。
- **一个地标 = 一个模块 = 一个负责人**。只有一个"集成人"能改共享文件，而且一次改一处。
- **候选文件夹**：新做的模型先放在隔离文件夹，经过比对才能替换正式资源，避免"重建把好东西覆盖掉"（他们真出过这种事故）。
- **"做 1 次 + 最多修 2 次，还不行就上报"**。
- **每个地标 8 项检查**：尺度、朝向、轮廓、周边环境、碰撞、浏览器实测、性能、来源。
- **"编译通过 ≠ 看起来对 ≠ 跑得快"** 写进了规矩。
- **性能看帧时间百分位**（p95/p99）和着色器编译次数，不只看平均帧率。

### 1.5 他们自己承认的问题

- 精力都花在了扩地图和做塔楼上，还加了坦克和导弹。
- 街道层面很空，密集区在 M1 Max 上只有 30–55 fps。
- 只能在电脑上玩，手机上只能看视频。
- 他们的结论是："先做好一条 1–1.5 公里的完整路线，再扩地图。"

## 2. 哪些值得学，哪些不适合我们

| 深城纪的做法 | 学不学 | 原因 |
|---|---|---|
| 用真实开放数据（OSM + 高程）铺满全城 | **学** | 旧金山的数据比深圳好得多：98% 的楼有真实高度（他们只有 3%），高程精度 7.5 米（他们 30 米）。 |
| 按距离分块加载、三级远近细节、加载和卸载设不同距离防抖 | **学** | 这是做全城的唯一办法。 |
| 一个地标一个模块，候选先隔离，只有一人集成 | **学** | 多个 AI 同时干活时不会互相覆盖。 |
| 8 项检查 + 帧时间百分位 + 着色器编译计数 | **学** | 能提前发现卡顿。 |
| 窗户"看不清就淡成平均色"、夜景整层亮灯 | **学**（用我们自己的着色器实现） | 从双子峰俯瞰全城时不会闪烁。 |
| 地标都有拍照机位、城市铺到地平线 | **学** | 这就是"大城市感"的来源。 |
| 照片级写实材质、HDR 天空、镜面反射水面 | **不学** | 和奶油色玩具微缩风格冲突，而且每张天空图要 6–20 MB。 |
| 340 MB 资源、启动时整城加载 | **不学** | 我们首屏必须 ≤ 3 MB，手机要流畅。 |
| 楼高随机、马路立交全部压平 | **不学** | 我们有真实楼高。旧金山的高架路做成不能走的"桥面"，不压平成地面。 |
| 坦克、导弹、撞飞路人 | **不学** | 不符合温馨的调性。车靠近时，路人会"跳开"并头顶冒个"！"。 |
| 无人机模式暂停整个世界 | **改着学** | 我们用鹈鹕滑翔俯瞰，世界照常运转。 |

## 3. 我们现在的差距

| 方面 | 深城纪 | Opus Bay 现在 |
|---|---|---|
| 覆盖范围 | 22.6 × 8.7 公里，1.6 万栋楼 | 只有 Embarcadero 一片，约占旧金山陆地的 **2.2%**，239 栋楼 |
| 远景 | 城市、山、海一直到天边 | 模型边缘外就是奶油色空白 |
| 地形 | 高程数据 + 山体 | 只有电报山一座手工山 |
| 地标 | 约 50 个 | 约 8 个（做得更可爱） |
| 移动 | 走、跑、开车、飞、瞬移 | 走、跑、跳、点地面自动走、叮当车 |
| 向导和真实信息 | 没有 | **我们有**：BAYBAY、带来源的真实信息、链接回 BAYLINK |
| 手机 | 不支持 | **我们支持**：390×844 下 60 fps |
| 性能 | 密集区 30–55 fps，约 1,150 次绘制 | 52–64 次绘制，4 倍降速下仍有 49–60 fps |
| 测试与流程 | 347 个测试、地标巡检脚本、百分位基准 | 104 个测试，还没有地标登记表和回归截图清单 |

**结论**：我们缺的是"面积"和"能快速穿城的方式"。步行手感、向导、真实信息、手机表现这几项，我们已经领先。

## 4. "整个旧金山"的整体方案

### 4.1 尺度：一眼能懂的数字

- **水平比例不变**：真实的 1 米等于游戏里 0.14 个单位。现有的一切（渡轮大厦、电报山、测试）都保持原样。
- **旧金山的陆地**在游戏里约 **2,070 × 2,520 个单位**。

| 从渡轮大厦出发 | 步行 | 跑步 | 骑车 | 鹈鹕滑翔 |
|---|---|---|---|---|
| 到双子峰（930 单位） | 3.7 分钟 | 2.1 分钟 | 81 秒 | 47 秒 |
| 到金门大桥南塔（1,076 单位） | 4.3 分钟 | 2.4 分钟 | 94 秒 | 54 秒 |
| 到海洋海滩（1,540 单位） | 6.1 分钟 | 3.4 分钟 | 134 秒 | 77 秒 |

- **山高曲线**："低处照旧放大、高处收一点"。

  | 地点 | 游戏高度 |
  |---|---|
  | 电报山 | 20（和现在完全吻合） |
  | 诺布山 | 23 |
  | 双子峰 | 50 |

  - 我用真实高程算过：99% 的地面坡度都在能走的范围内，只有约 1% 的悬崖和采石场走不上去。
  - 如果不"收一点"，双子峰会高达 65，西半城会像一堵墙。
- **房子高度**：用一条公式，正好还原现在手调的数值（维多利亚小楼约 5，泛美金字塔 41，Salesforce 塔 56.5）。
- **合并成玩具屋**：旧金山真实的地块只有 7.6 米宽，按比例缩下来太细。所以把相邻约 4 块合成一栋"玩具屋"，全城约 **4.5 万栋**（真实约 16 万栋）。
- **街道宽度**：用"玩具尺寸"（住宅街 3.6，主干道 5.6，和现在一致），整条街都能走。
- **台阶**：全城 2,618 段台阶都会做成可爬的阶梯。爬台阶本来就是旧金山的招牌动作，Filbert 台阶已经这样做了。

### 4.2 社区与地标：清单与优先级

**先做三条"精做路线"**。每条都对应 BAYLINK 里已有的指南或行程。三条都做到街道级别的好品质，再往外扩：

1. 唐人街 → 北滩 → 科伊特塔
2. 码头区 → 艺术宫 → 克里西原野 → 金门大桥
3. 金门公园（无车 JFK 步道）→ 海洋海滩

**第一梯队**：从好几个社区都能看见的"天际线指南针"。
- 金门大桥
- 苏特罗电视塔：全世界最高点，走到哪都能用来辨方向
- 双子峰观景台
- 市政厅圆顶
- 艺术宫
- 金门公园（含德扬博物馆塔）
- 海湾大桥（移到真实位置）
- 现有的 Salesforce 塔、泛美金字塔、科伊特塔、渡轮大厦
- 恶魔岛（移到真实位置，放大 1.3 倍，保证望远镜里还看得清）

**第二梯队**：社区地标，每个都有小广场和信息卡。
- 彩绘淑女屋（阿拉莫广场）、唐人街龙门、九曲花街
- 渔人码头、海德街码头、吉尔德利广场
- 花卉温室、荷兰风车

- 悬崖屋与苏特罗浴场、要塞区隧道公园、日本城和平塔

**第三梯队**：点缀。
- 海浪风琴、贝克海滩、伯纳尔山、戴维森山十字架、斯托湖
- 16 大道马赛克台阶、巴尔米巷壁画（只做原创壁画）
- 金门公园野牛、电报山鹦鹉

**规矩**：每做完一个地标，都要把它周围 150–300 米的街道也做好，才能开始下一个。不让一座塔孤零零立在空地上。

### 4.3 数据与分块加载（像地图 App 一样按块加载）

**数据已经全部下载好**，在 `C:/Users/willy/opus-qa/sf-data/`，约 614 MB，都是原始数据，不会进游戏包：
- 16 万栋楼的轮廓和高度（OSM + 旧金山政府的激光测高）；
- 4,552 公里道路和 2,618 段台阶；
- 缆车、叮当车、渡轮线路；
- 7.5 米精度高程；
- 41 个社区边界；
- 69 个地标的精确坐标。

**离线把数据压成小文件**：
- 全城切成 128 × 128 单位（约 900 米见方）的块，有陆地的约 195 块。
- 每块压缩后约 20 KB，**全城合计约 4–5 MB**。
- 另有一个约 400 KB 的"远景全城"文件。

对比一下：深城纪一个楼文件就 50 MB。

**三级远近细节**：

| 距离（高画质 / 中 / 低） | 显示内容 |
|---|---|
| 150 / 120 / 90 单位以内 | 完整玩具屋：窗户、屋顶、凸窗、路灯、树 |
| 520 / 420 / 320 单位以内 | 带颜色和屋顶的简单盒子 |
| 更远 | 整个街区一个体块，但**保留颜色**（深城纪把远景做成灰盒子，后来自己拆掉了） |

**不卡顿的做法**：
- 在后台线程里生成模型，每帧最多往场景里放 1 个新块。
- 快速旅行时，BAYBAY 的鹈鹕会在"云里"等目的地加载好再降落。

**首屏不变**：标题画面和现在一样快；全城的远景在开场过场动画时悄悄加载。

**保底开关**：先用网址参数 `?world=city` 开启全城模式。等验收通过后，再把它改成默认。

### 4.4 保持玩具微缩风格

- **整座旧金山是桌上的一块模型**：
  - 南边沿县界是一刀切开的"地层剖面"；
  - 海水边缘是玻璃般的切面；
  - 马林岬角（金门大桥北端）和东湾是旁边的几块"小板子"。
  - 不用照片天空，也不用画出来的远山长图。
- **社区配色**：

  | 社区 | 配色 |
  |---|---|
  | 维多利亚区、日落区、教会区 | 粉彩 |
  | 金融区、SoMa | 中性的石色和砖色 |
  | 唐人街 | 红绿金点缀 |

  新增三种窗户样式：SoMa 拱形仓库窗、唐人街阳台带、日落区车库带。
- **远处也保留颜色和屋顶**：从双子峰往下看，是一整片彩色的玩具城，不是灰盒子。
- **"Karl the Fog"**：旧金山招牌的海雾，做成棉花团一样的雾墙。早晨和黄昏会从太平洋一侧慢慢漫进金门，盖住双子峰。这是只有旧金山才有的氛围。
- **夜景**：窗户按整层、整户亮灯；只给离你最近的 64 盏路灯加光晕，保证手机也跑得动。

### 4.5 Higgsfield 资产计划与花费

- **原则**：AI 只做代码做不好的东西，也就是雕花装饰、有机形状和插画。

## 5. 移动与行动机制升级

| 方式 | 怎么玩 | 关键数字 |
|---|---|---|
| **步行 / 跑 / 跳** | 手感保持不变（我们本来就比深城纪好）。新增坡度：上坡变慢，下坡稍快，太陡的坡上不去，台阶走得稳。 | 走 4.2、跑 7.5。上坡最多慢到 55%。坡度超过 0.9 就爬不上去（约 1% 的地面）。 |
| **长跑喘气** | 不设体力条。连续上坡跑 10 秒后，到坡顶会喘两口气，BAYBAY 也会调侃一句。 | 60 秒内不重复 |

## 7. 风险与取舍

1. **手机卡顿**：全城加载最怕手机掉帧。
   - 应对：模型在后台线程生成，每帧只放一块；每个阶段都在手机尺寸加 4 倍降速下测，要求 ≥ 45 fps。
2. **新旧接缝**：现在的 Embarcadero 是手工做的，而且海滨往海湾里"外推"了约 130 米真实距离。
   - 应对：街区整块划归一方，新城在 40 单位宽的带子里平滑接上高度，海岸线的偏移在 160 单位内逐渐消失。
3. **远处像灰盒子**：深城纪踩过这个坑。
   - 应对：远景保留颜色和屋顶，每个社区有自己的配色。
4. **铺太宽、街道太空**：深城纪的教训。
   - 应对：三条精做路线先达标，才往外扩第二和第三梯队。
5. **切换时卡一下**：着色器临时重新编译会导致卡顿。
   - 应对：启动时预热，行走中不开关灯光，用测试盯住编译次数。
6. **坡太陡**：现在的角色能爬任何坡。
   - 应对：加坡度规则，大约 1% 的悬崖变得不能走。
7. **数据错误**：高程把海湾大桥桥墩当成陆地、2010 年的测高里没有 Salesforce 塔。
   - 应对：陆地用海岸线划定，楼高优先用最新数据，地标手工覆盖。
8. **花冤枉钱**：
   - 应对：先做 57 分的选拔赛，有止损规则，每个 AI 资产都备好代码做的替代品。

**取舍**：
- 旧金山走一趟要 3–6 分钟，**我们不缩小城市**，改用交通工具和快速旅行解决。
- 玩具小车只是"儿童车"大小，不搞 GTA 式的飙车。
- 这一轮不做 AI 立面贴图和远景画卷，保持玩具风格统一。
